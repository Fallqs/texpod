# 系统架构

## 数据流与所有权

```text
任意阅读 App → Android 系统 TTS 请求 → Texpod Mock TTS
  → 有界接收队列 → 规则断段与固定网格分页 → 共享字形 LRU
  → 手机保留可回溯文本、预览位置和相邻页排版结果
  ├→ 同一 1bpp 页面 → 手机屏幕预览（默认，无需阅读器）
  └→ 可选按需推页（字形增量 + 网格，或 1bpp 位图）→ BLE → Texpod 固件
     ← 前翻 / 后翻请求、显示确认 ← 逻辑按键 / GfxRenderer / HalDisplay
```

**手机拥有正文和两个独立的阅读位置。** 它只拥有 TTS 已交付的内容，不假定整本书可用。手机保留相邻页所需的文本或排版结果；后退无需原 App 倒读。手机预览游标可自由前后移动，不覆盖设备已确认的页面位置。只有阅读器成功提交显示后，手机才确认设备投读位置。来源改变、清除或明确重新开始时开启新会话，不猜测两段文字是否可拼接。

**设备是显示终端。** 它只保留当前画面及其标识、一个当前待接收或待绘制的页面、一个有界 RAM 字形 LRU。手机另有有界栅格 LRU 和设备元数据镜像。收到完整页面后，设备校验基修订号、槽位绑定和依赖，再绘制到唯一帧缓冲；显示提交时同步提交字典绑定与 LRU 顺序，随后丢弃页面指令，不建立设备端历史。重发同一个推送时只回复已提交结果，不重新刷屏或提升 LRU。

## 翻页行为

- 进入会话时由手机推送锚点页；此后每次前翻或后翻都由阅读器按当前画面发请求，手机推送目标页。用户可以按 `12 → 13 → 12` 阅读，推送序号不倒退。
- 手机可以预排相邻页，但首版不提前发送下一页或缓存历史页。设备一次只受理一个翻页请求；等待或刷屏时不累计按键。
- 无可推送的页时，统一应答 `NO_PAGE` 并保留当前画面；用户去手机处理朗读来源。断连、校验失败或超时也不推进位置，但属于传输故障。
- 重连不恢复设备缓存或在途请求。手机以最后能确认的位置重新推送锚点；没有确认的翻页不猜测推进。深睡后的画面保留取决于现有睡眠模式，不依赖保留画面恢复正文状态。

## 数据面

- `PAGE_GRID`：手机推送本页字形增量与网格操作符；字形可跨推送复用，命中页也在显示确认后更新 LRU。设备不能缺一个字问一次手机。容量不足时先淘汰本页工作集之外的旧条目并显式重绑槽位；无法安全安放时整体重置或回退位图，不保存依赖缓存的旧页。
- `PAGE_BITMAP`：同版面的 1bpp 位图，用于真机端到端基线及单页图集溢出等回退。原始整屏为 X4 48,000 B、X3 52,272 B；冷图集也可能比位图更大，两者应实测。若用 SD，设备只暂存并验证**一个在途位图**，不把它当成历史页缓存。
- 不发送富文本，不在设备解析 EPUB、TTF、OTF 或 `.cpfont`，不为不同语言在固件加入排版分支。

## 固件集成边界

- 当前从 Apps 进入独立 `TextPlayerActivity`，不把完整 `EpubReaderActivity` 留在栈底。
- 渲染经 `GfxRenderer`/`GUI` 与 `HalDisplay`，使用运行时逻辑视口和安全区；输入用 `MappedInputManager::Button`。一个手势只触发一个动作，继承的按键释放不重复翻页。若需位图暂存，经 `HalStorage`/`HalFile` 顺序读写并清理。
- BLE 回调只交付有界数据，不直接刷屏；共享渲染任务拥有帧缓冲。只有整页通过验证、渲染并成功提交后才发 `DISPLAYED`。退出和睡眠不可持 `RenderLock` 等待还需该锁的任务。
- 固件 Texpod 进入时先停止现有 HID Central，成功后才启动 BLE Peripheral；两者通过 NimBLE 的全局初始化所有权互斥，不共享连接。退出与睡眠先停止 Peripheral 再释放缓存。BLE 扫描、GATT 回调、发送队列和阅读状态统一串行到 Android 主线程，避免与分页和预览竞争。
- 首版没有持久字形或页面格式。如果将来引入，先定义格式版本，再同步 [文件格式](../docs/file-formats.md)和[缓存管理](../docs/engineering/cache-management.md)文档。

## C3 资源与生命周期

X3/X4 共用无 PSRAM 的 ESP32-C3，约 380 KB 可用 RAM，且只有一块面板帧缓冲。[设备差异](../docs/engineering/device-variants.md)列出真实尺寸。现有 X3 HID 栈启动实测消耗约 50–51 kB，阅读器门槛为 80 KiB 空闲堆、32 KiB 最大连续块，见 [RadioPolicy.h](../lib/BlePageTurner/src/RadioPolicy.h) 和 [BleInput.h](../src/BleInput.h)。[C3 配置](../src/platform/NimbleC3Config.h)现同时启用 Central/Observer 和 Peripheral/Broadcaster，首选 ATT MTU 为 23。这些是配置与历史实测证据，不是新角色的预算或吞吐承诺。

当前实现把接收事件限制为 8 个、单帧 240 字节，C3 字形池为 16 KiB，256 个槽位，2048 个原始 token；大块分配只在 Activity 进入时进行一次，退出释放，位图页暂存于 SD。不得分配第二块全屏 RAM，也不以降低现有 HID 门槛通过验收。BLE、缓冲与任务只在投读期间存活；等待配对、断线重试与空闲等待必须有界，连接本身不阻止自动睡眠。退出或睡眠释放资源并清理暂存；不承诺后台常驻。使用经用户确认的加密连接，CRC 只检错；正文不进普通日志，手机保留的文本和设备暂存均按内容数据处理。真实峰值、连续块和任务栈余量仍待真机测量。
