# Texpod 设计蓝图

> 状态：**Texpod 的 Android 系统 Mock TTS、独立手机预览、可选 BLE 推页、双端 LRU 和固件网格/位图显示代码已实现**。任意来源自动开始、预览排版与像素一致性由主机测试覆盖；Android 目标 App 的真实 TTS、手机实机界面、X3/X4 显示、配对翻页、生命周期和端到端投读尚未完成真机验收，不能视为稳定版本。

Texpod 是手机与电子纸阅读终端的名称，Android 伴侣 App 和 CrossMux 固件 Apps 中的入口都显示为 **Texpod**。手机通过系统 Mock TTS 接收阅读 App 主动提交的文字，重新断段、分页和栅格化；页面可直接显示在手机上，也可通过 BLE 镜像到阅读器。阅读器只处理前后翻信号、字形贴图和刷屏。

## 首版决定

1. **一次系统设置，任意 App 直接朗读。** 用户只需把系统首选 TTS 引擎设为 Texpod，然后在阅读 App 中开启朗读；不需要在伴侣 App 选择来源、开启投读开关或导入 EPUB/TXT。Texpod 不绑定任何特定阅读 App，不依赖 MultiTTS 或其语音包。内置样例仅用于独立预览测试。
2. **手机预览是默认输出，不是 BLE 的附属调试页。** 无阅读器、无蓝牙权限时也能接收 TTS、显示页面、前后翻和清除会话。未连接时使用手机预览网格；连接后按实际设备能力与视口排版。手机和发送给设备的页面共用同一套 token、字形 LRU 和 1bpp 编码，不用另一套 Android 文本布局假装一致。
3. **只整理收到的文本。** 用规则添加段落、缩进等结构，优先保证可读；不还原原书版式，也不承诺 TTS 能取得全书。段落边界可不同，但不擅改或丢弃已接收的正文。
4. **前后翻都是推页。** 手机保存已获得的正文和分页位置。阅读器只发前进或后退请求；不保存、不重放旧页，不独立跳页，也不承诺断连翻页。页序可以前后移动，传输顺序独立递增。
5. **没有可推送的相邻页，就保留当前画面。** 缺文、朗读中断和内容结束对设备统一为 `NO_PAGE`；用户在手机侧处理。BLE 超时是传输故障，不改变设备当前位置。
6. **固定网格就是版式。** 首版采用单一、横排、易读的正文主题；分段、网格分页、字形栅格化全部在手机完成。字形图集＋`PAGE_GRID` 是主路径；`PAGE_BITMAP` 仅作基线与必要回退，不做逐字坐标或通用排版协议。
7. **初版即使用双端 LRU，只复用字形，不复用设备上的旧页面。** 手机维护有界栅格 LRU，设备维护有上限的 RAM 字形 LRU，手机保存设备元数据镜像；槽位可按确定性 LRU 规则淘汰重绑，缓存状态随 `DISPLAYED` 原子确认。不做 SD 冷字形、跨重启持久镜像或设备端页面预取，可以在手机预排相邻页。
8. **投读期间才持有设备资源。** 固件 Texpod 与现有 BLE HID 翻页遥控器互斥；设备不加载字体文件、不分配第二个全屏缓冲，退出和睡眠要停止会话并释放资源。手机预览使用一块有上限、可复用的 ARGB 表面，不保存历史整页位图。

Mock TTS 不是通用书籍导出接口；不绕过 DRM，不处理未交给系统 TTS 的文本，不做无障碍自动滑屏或 OCR。首版不支持 iOS、复杂印刷版式、选字、词典或整本离线阅读。
