# 双端 LRU 字形缓存

## 目的与边界

初版即采用双端 LRU：手机维护有界的栅格字形 LRU，设备维护固定容量的 RAM 字形 LRU；手机另存设备缓存的元数据镜像，只随本页推送缺少的图块。设备不保存页面历史，不做逐字按需请求、SD 冷字形或跨重启缓存恢复。

Texpod 的手机预览与 BLE 编码共用同一个栅格 LRU。预览只消费手机图块，不会向设备缓存镜像提交候选，也不会伪造 `DISPLAYED`。没有阅读器时，手机仍按同一字形身份和确定性规则生成 1bpp 页面；接入设备后才根据协商容量建立设备镜像，按以下规则推送页面。

> 同一 `cacheEpoch` 中允许显式淘汰并重绑 `slotId`，但每次变更必须与页面显示原子提交。一次推送引用的全部槽位都是本页工作集，在完成绘制前不可被清空、覆盖或回收；已经显示的页面只剩像素，不再依赖字典。

## 字形身份与双端所有权

- 手机用 `GlyphKey` 标识实际图块。身份覆盖实际字体及变体、glyph 或 ASCII 文本图块内容、字号、绘制样式、像素格式和栅格化规则；只要影响位图或相对基线的偏移，就不能误共享。ASCII 图块的身份包含**完整文本**，不能只取首个码点或假设无碰撞的摘要；一个 ASCII 图块按实测宽度前进一个或多个网格单元，并在 token 流中显式携带跨度。整数位置、单主题、1bpp 可减少维度。手机的页面模型保留绘制单元身份，**发送时**才按当前设备镜像转成 `slotId`。
- **手机栅格 LRU** 保存 `GlyphKey → 栅格图块`，按字节数和条目数双重限容，访问时提升为最近使用。它可以独立淘汰图块；之后按同一确定性栅格化规则重新生成，不能因此改变 `GlyphKey` 或设备镜像。栅格 LRU 的命中不等于设备仍持有该字形。
- **设备缓存镜像** 保存 `GlyphKey → slotId`、位图池范围、字节成本以及设备 LRU 顺序。它只表示已确认的设备状态，不是第二份设备位图池，也不因手机栅格 LRU 淘汰而自行删除条目。
- **设备 RAM LRU** 只存 `slotId` 对应的宽、高、相对基线偏移、位图池范围和数据。能力协商给出字节上限、槽位上限和修订号宽度；索引、对齐、位图池、候选变更记录和本页缓冲均计入 RAM 预算。批量处理时不为每个 glyph 单独动态分配，也不加载整套字体。

## 一致状态与页面候选

设备与手机镜像共同以 `(cacheEpoch, cacheRevision)` 标识**已显示确认**的缓存状态。会话从空字典和约定的初始纪元、修订号零开始；`occupiedSlots` 只用于容量核对和诊断，不能单独作为同步锚点。

每个 `PAGE_GRID` 携带基状态、目标状态和显式字形绑定描述。绑定至少包含 `slotId`、位图池范围、图块长度和图块内容，不再以 `occupiedSlots` 隐式推断追加起点。手机从已确认镜像构造一个候选：

1. 计算目标页全部 `GlyphKey` 和 token 流，将对应槽位标记为本页工作集；工作集内条目不得淘汰。
2. 新字形优先使用空槽和空闲位图范围，再按 LRU 从旧到新淘汰**不在工作集内**的条目，直到槽位和字节预算都足够。位图池范围由手机镜像明确分配，设备验证对齐、边界和重叠；不允许设备悄悄移动已确认条目。
3. 槽位重绑只出现在本次候选的显式绑定中。不得复用仍被本页 token 引用的旧绑定，也不得附带本页不引用的新字形。相同 `pushSeq` 的重发必须保持相同载荷。
4. 普通 `PAGE_GRID` 的目标修订号为基修订号加一。整表重置同时递增 `cacheEpoch`，从空字典放入本页全部工作集，并以重置后的首个修订号提交。编号不得回绕；接近协议上限时结束会话并重新握手。
5. 若本页工作集超出槽位数或位图字节预算，改推 `PAGE_BITMAP`。位图不依赖字典，也不改变字典内容、LRU 顺序、`cacheEpoch` 或 `cacheRevision`。若回退不可用，报告资源错误并保持当前位置，不把它当成正文结束。

设备先验证基状态、绑定数量、图块长度、位图范围、总容量、网格语法以及全部槽位引用，再使用候选映射绘制。候选只允许覆盖已确认被本候选淘汰的位图范围；在整页显示提交前，候选条目和 LRU 顺序不得成为已提交状态，也不分配第二份完整字典或第二个全屏缓冲。

## LRU 的确定顺序与原子确认

同一页内只按 token 流计算一次确定的最终顺序：取本页每个被引用槽位**最后一次出现**的位置，按该位置从先到后排列，依次从较旧到最新提升；未被本页引用的保留条目全部排在它们之前。手机和设备必须使用同一算法，不能只按新增字形或网络包到达顺序更新 LRU。

成功的 `DISPLAYED(sessionId, pushSeq, pageId, cacheEpoch, cacheRevision, occupiedSlots)` 同时确认屏幕、字典绑定和 LRU 顺序。设备以 `GfxRenderer::displayCommitted()` 成功为提交点；手机只有收到匹配的 `DISPLAYED` 才把候选替换为已确认镜像，BLE 写入成功不代表缓存更新。`PAGE_BITMAP` 的确认回传原缓存状态和 LRU 顺序。

同一推送重复到达时，设备只重发原 `DISPLAYED`，不得再次写字典、提升 LRU 或增加修订号。校验、接收、绘制或显示失败，以及确认不明时，只要不能严格证明两端仍一致，就结束会话并以空字典重新握手；尤其候选已覆盖旧位图后，不得靠保留旧元数据假装缓存仍完整。断连、设备重启、布局会话更换或手机镜像丢失同样从空字典开始，不维护摘要、跨连接事务重放或旧页引用。

前翻和后翻使用相同过程。即使目标页曾经显示过，设备仍接收新的推送；命中设备 LRU 的字形无需重传，其 recency 仍随成功显示更新。手机栅格 LRU 可跨页面复用图块，但设备镜像是否命中必须独立判断。
