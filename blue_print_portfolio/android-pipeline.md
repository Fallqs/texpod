# Android 内容管线

## 系统 TTS 是唯一外部入口

用户只需在系统 TTS 设置中将 **Texpod** 选为首选引擎，然后到任意阅读 App 开启朗读。伴侣 App 不提供来源选择器，也不要求额外点击“开始投读”。Texpod 以系统 TTS 引擎注册，不注入或控制来源 App。想恢复有声朗读时，在系统设置中切回原来的 TTS 引擎即可。首版不要求导入 EPUB/TXT；“试试示例”只验证本地排版和预览，不代表从第三方 App 取文。

**注册兼容性（0.1.1）：** 0.1.0 的 TTS intent-filter 漏了 `android.intent.category.DEFAULT`。AOSP [`TtsEngines.getEngines()`](https://android.googlesource.com/platform/frameworks/base/+/main/core/java/android/speech/tts/TtsEngines.java) 以 `MATCH_DEFAULT_ONLY` 查询，因此该 APK 不会出现在系统引擎列表中。0.1.1 补上 DEFAULT、`android.speech.tts` 元数据和 `CHECK_TTS_DATA` 的 `TtsDataActivity`，并声明 Android 11 的 TTS 服务查询。从 0.3.1 起，元数据指向独立的 Texpod 设置页，与主界面右上角设置入口打开的是同一页；不需要 `QUERY_ALL_PACKAGES`。清单回归测试直接检查这些注册条件，真机系统列表仍须在安装新版后复核。

参考 [MultiTTS 的公开使用流程（第三方说明）](https://www.danji100.com/app/174124.html)：它展示了让阅读 App 选用第三方系统 TTS 引擎的交互，可作为引擎选用、切回以及兼容性验证的对照。**不将 MultiTTS、语音包或源码作为依赖**，也不据此假定目标 App 会接受静音引擎或自动提交下一段。

技术契约以 Android 的 [`TextToSpeechService`](https://developer.android.com/reference/android/speech/tts/TextToSpeechService) 和 [`SynthesisCallback`](https://developer.android.com/reference/android/speech/tts/SynthesisCallback) 为准：

- 在 `onSynthesizeText()` 中从 `SynthesisRequest` 读取 App 主动提交的内容，不要求用户预先选择来源包名。`callerUid` 解析出的包名仅用于会话隔离和状态显示，不是允许列表；包名不可解析时使用 UID 名称或 `uid:<id>`，避免所有未知来源混成一条流。首个请求自动开启会话，空请求不清空已有内容。
- `TtsIngester` 给最新来源唯一活动所有权并隔离旧会话。被分离来源的迟到请求返回 `ERROR_INVALID_REQUEST`，不能抢回预览；活动流停止后自动释放所有权，任意 App 的下一次朗读可直接接管，不需要回 Texpod 清除。Android 只有一个合成线程，且只让来源 App 停止自己的请求，因此 Texpod 不能强制暂停另一个 App 的界面；若旧请求正受页数背压，新来源要在该请求解除等待后才能由系统交付，不能把被动切换宣称为跨 App 强制控制。
- TTS 块可能是句、段或一屏，不是段落或页面边界。Mock TTS 不具备全书随机访问、原书进度或可靠结束信号，也不直接操控原 App 页码。
- `ReadingFlowGate` 在当前渲染页前方已有 3 页时停止接收后续文本。未连接阅读器时以手机预览页为准；连接后以设备最后确认 `DISPLAYED` 的页为准，预处理和取消的翻页不推进锚点。`LocalReading.appendRange()` 按码点释放原文且保留原始 TTS 块边界。即使当前 utterance 的全部文本已排版，窗口已满时也暂不完成静音合成，避免来源应用因此继续提交下一段。快退后不删除已排版页，但在重新腾出空间之前不会补入新文本。`onStop()`、清除或来源切换取消等待；不为绕过背压异步持有 callback。
- 合成保持 Android 要求的同步调用，接收队列仍有界；等待页数窗口是明确的阅读背压，不是网络忙等。静音输出、长块等待、回调时序和跨 App 切换以目标 App 实测为准。来源 App 内部换书或跳页没有可靠的通用信号，仍不能猜测内容关系或按相同文字去重。

## 手机独立预览与界面

`android/` 使用 Java 和 Android 公共 API，无第三方运行时依赖。`TextPlayerTtsService` 以 16 kHz、单声道、16-bit PCM 返回 20 ms 静音；仅在阅读器连接时按已确认页面施加背压，不把 BLE 写入成功当作渲染进度。`TtsIngester` 和 `ReadingFlowGate` 是无 Android 依赖的来源切换、等待与恢复策略，可直接进行 JVM 测试。`TextPlayerSession` 以世代号隔离清除/重开，使用 32 块接收队列、250 ms 有界入队等待、单块 16,000 字符和总会话 1,000,000 字符上限；溢出进入明确错误状态，下一次朗读可以开启新会话。正文、队列和 LRU 均为易失数据，清除会删除当前会话，但不会更改系统首选引擎。

未连接阅读器时，`ReaderProfile.phonePreview()` 的默认配置为 480×800 视口、24 px 字形、14×36 半格、30 列×20 行和 2048 原始 token 上限。每个汉字占两个半格，仍保留原有 28 px 字距。Texpod 设置页提供 18–36 px 字号与即时示例，并将 Android 系统 TTS 入口放在独立卡片。应用字号后，设置仍持久保存；清空手机栅格 LRU，按新版式从当前页首字符前后重新分页，不重置已向 TTS 确认的消费进度。界面只显示前后可翻的近似页数，不显示绝对页码或全书总页数。连接阅读器时重新协商并重置设备缓存，保留设备最后确认页的首字符，即使手机正浏览不同页面。连接后按设备安全区、视口、token 和缓存容量排版；来源文本直接驱动预览，BLE 关闭或失败不影响继续阅读。

0.1.2 通过 Android `WindowInsets` 显式应用状态栏、导航栏和刘海安全区；API 30+ 合并 systemBars/displayCutout，API 28–29 合并旧式系统窗口与 cutout，API 26–27 使用系统窗口 insets。滚动容器裁切到安全 padding，页面顶部和底部控制不再位于系统栏下面。

0.2.0 的 `TextRunPacker` 用与栅格化相同的 `Paint` 测量连续 ASCII 字母、数字、空格和标点，将完整文本栅格化为一个图块，以 `ASCII_RUN`、槽位和实测单元跨度发送。单词能放入整行但不能放入当前行余量时先换行；只有超过整行的长词才拆分，不再把 `Android` 等词挤进固定宽度小图块。单个图块仍受 1 KiB 上限约束。CJK 和其他 Unicode 码点默认各占一格；0.3.1 将 `：“`、`: “`、`。”` 等符合规则的组合栅格化为一个普通字形槽，占一格，不修改固件协议。显式换行仍是分隔边界。未完成的词跨 TTS 块保留，未交付页可更新；预览会计算完整 pending run 的分页，翻走或发送给设备后才封存，且发送给设备的页面即使不是手机当前浏览页也必须封存。

0.4.1 改用半格量化：ASCII 文本段按测量宽度占用半格，汉字和合并标点仍占两个半格；手机预览和阅读器使用相同的换行位置。中文左双引号 `“`（含连续两个反引号的等价写法）贴齐全宽格右上角。0.4.4 起，`！”`、`。”` 等合并标点末尾的闭合引号也对齐到同一格的右侧；独立的右双引号及单个反引号仍保持原位置。

`LocalReading` 保留页面历史和独立的手机预览游标。正在显示的短页可随后续文本自然增长；用户翻走或页面发送给设备后封存，回退时页面不会悄悄改变。手机上的上一页/下一页只浏览本地预览，不强行改变设备的在途翻页；设备按键仍以设备已确认页面为锚点。二者使用相同分页历史，但不要求用户浏览手机时设备同步翻页。

`PageBitmapEncoder.rasterize()` 将同一页 token 和字形栅格合成为 1bpp 像素；手机 `ReaderPreviewView` 显示这些像素，`PAGE_BITMAP` 也从此编码。`PageEncoder` 和手机位图编码共享有界 `RasterGlyphLru`，避免手机预览与设备网格分别生成不同字形。主机测试直接比较本地预览与传输位图的像素，而不只检查页面数量。

手机只保留一块当前尺寸的 `ARGB_8888` 显示表面和一个同尺寸的 `int[]` 转换数组：本地 480×800 时合计 3,072,000 B，协商上限为 1,000,000 像素（合计 8,000,000 B），替换尺寸或退出界面时释放；另保留 256 KiB 栅格数据 LRU 和当前 1bpp 页面，不缓存历史整页位图。该手机内存预算与 ESP32-C3 的单帧缓冲约束不同，不能把 Android 内存开销算入设备静态 RAM，也不能因此在固件增加第二块全屏缓冲。

界面以大幅纸张预览为中心，采用暖灰背景、墨色文字、珊瑚红强调色、圆角卡片和明确的阅读/连接状态。系统 TTS 设置是主要引导，BLE 是可选的“连接阅读器”操作。所有用户文案均来自 Android 资源，提供英文和简体中文。

连接按钮下方的「阅读器性能」可展开查看协商后的屏幕、网格、字形缓存、ATT MTU 和帧上限。面板显示在途页及最近确认显示页的编码、正文大小、GATT 特征值字节数、分片数和耗时。传输速率按正文大小除以首次写入至末次写入回调的耗时计算，不代表空口速率。旧固件仍可接收页面并显示手机侧数据；更新固件后可分别查看分片到达跨度、SD 暂存、页面准备、绘制等待、绘制和刷屏。BLE 写入与设备接收部分重叠，不能把两者相加。

Android 在发送页面前尽力请求 BLE 高优先级，连续发页时复用请求，最后一次页面写入进展约 2 秒后请求恢复均衡优先级。请求成功提交不代表连接参数已改变；支持的固件随 `DISPLAYED` 报告首片和末片到达时的实际连接间隔。双方支持时，页面以无 ATT 应答的写命令发送，一次只提交一个 Android GATT 写操作，依靠本地回调继续提交同批的下一片，至多六片后等待阅读器的 `PAGE_CREDIT`。本地回调不证明送达；性能面板分开显示手机回调耗时和阅读器实测到达跨度。旧版组合仍逐片等待 ATT 写入应答。不为优先级协商等待，也不改变页面格式。

「分片流量」实时显示最近四条记录，可查看和复制最多 512 条历史记录。每条记录包含方向、连接后的回调时间、类型、对象号、正文偏移、GATT 特征值字节数、写入至回调耗时及状态（仅 TX）和应用分发耗时。断开后可查看，尝试新连接时清空；记录只保存在手机内存中，不存储正文或上传。测试时可比较首次显示、后续翻页和退回已读页的结果。

### SD 字形流（Android 12+ 和支持此功能的固件）

连接时按字号、字体数据和字形栅格化版本查询 SD 卡上的字体包。已有对应版本时直接开始会话；没有时，手机在后台生成完整字形包并分块上传，界面显示准备和传输进度。安装完成后，每页只发送网格上的字形编号和位置，不发送字形位图；阅读器的 RAM 缓存未命中时从 SD 读入，不写回 SD。字体回退需要新的字形面时，手机保留目标页并重新协商扩充字体包，不回退到位图传输。旧固件或 Android 11 及更早版本仍使用原有网格/位图协议。

「阅读器性能」可确认页面是否使用「SD 字形流」，并区分手机收到翻页请求到显示确认的时间、BLE 传输、逐片解码绘制和面板刷新。首次生成或安装字体包不计为普通翻页。「重新安装字形包」在确认后强制替换当前字号的字体包，和固件的 SD 卡升级及恢复入口无关。

## 断段、分页与手机历史

```text
有序 TTS 文本块 → 规范化空白并添加结构标记 → 固定网格分页
  → 手机页面范围与坐标 → 共享手机栅格 LRU（未命中才栅格化）
  ├→ 同一 1bpp 页面 → 手机屏幕预览
  └→ 按设备 LRU 镜像分配/淘汰槽位 → 字形增量＋网格 / 位图
```

- 在手机会话中保存已接收文本及来源范围。`ParagraphRules` 用可解释规则恢复块间段落：句末标点结束当前段，完整的“第 N 章 标题”或“Chapter N Title”块前后断段，句中相邻块直接连接；显式换行保持原样，不重复插入。TTS 块本身不必然等于原书段落，这些只是通用启发式规则，不使用生成式模型改写。验收针对接收到的正文，不对 TTS 上游的遗漏、重读或改写作保证。
- 仅对流尾保留有界判断窗口；允许输出短页，不因等待下一块而无限延迟首屏。已交付或已经翻走的版面在同一会话内不被后来输入悄悄改写。没排出所请求的相邻页就回 `NO_PAGE`，不把暂时没有输入推断为全书结束。
- TTS 换源或停止后重新朗读时，只保留旧流的当前页作为过渡，丢弃其余旧页。第一次向任一方向翻页都进入新流的第一页，以后只能浏览新流；若新流还未排版出页面，则仍停在过渡页。连着阅读器时以设备的 `DISPLAYED` 确认为锚点；若已有一页在途，则等该页确认后切换。手机和设备各自翻离过渡页后才能释放它。

## 固定网格直接用于排版

- 首版以横排中文阅读为主，用一套固定主题处理页边距、字号、行距、段距、首行缩进和常见标点禁则，同时用实际样本挑选可读的拉丁字母、数字与中文混排方式。按设备报告的可用视口算行列，不固定设备尺寸。
- 手机直接确定单元格和基线，不先做通用段落排版再拟合网格。不要求连字、复杂双向文字、多主题或复制原书样式；ASCII 文本按实际字体测量宽度，CJK 仍使用固定单元格。
- 图集项对应由手机确定的绘制单元，可以是单个字形，或带显式跨度的 ASCII 文本图块；不要按 UTF-16 代码单元拆字符。超出网格能力但手机能正常绘制的页面可走 `PAGE_BITMAP`；不引入通用自由坐标 `PAGE_RUNS`。不支持的字符或排版不能悄悄从正文删掉。
- 首版使用整数坐标和 1bpp 黑白输出。手机在已知原点绘制图块，裁掉空边后保留相对基线的偏移；透明背景不擦掉相邻字形。用同一版式比较手机参考画面和设备重建，检查 overhang、裁剪和字体回退。
- 字形路径优先用 Android 公共绘图 API；若需要直接取得 glyph ID 和位置，可用 API 31+ 的 [`TextRunShaper`](https://developer.android.com/reference/android/graphics/text/TextRunShaper)、[`PositionedGlyphs`](https://developer.android.com/reference/android/graphics/text/PositionedGlyphs) 与 [`Canvas.drawGlyphs`](https://developer.android.com/reference/android/graphics/Canvas)。它们不是将 `StaticLayout` 引入主路径的理由，也不因此引入 HarfBuzz/FreeType。

## 会话控制与验证

手机统一负责取文、分页历史、手机浏览位置、设备翻页目标以及可选 BLE 推送。连接状态由底部连接/断开按钮表达，正文接收状态和错误在预览下方显示；活跃会话显示通知，后台限制和进程回收仍需真机验证。阅读器的翻页只消费手机已有内容，不触发模拟滑屏或原 App 跳页。

标准验证命令为 `cd android && ./gradlew testDebugUnitTest assembleDebug lintDebug`（Windows 可用 `gradlew.bat`）。没有阅读器时可点击“试试示例”验证首屏、增页、前后翻、清除及屏幕旋转，也可从任意 App 发起系统 TTS 并观察同一预览。真实目标 App 的静音持续推进、锁屏和进程回收仍需真机验收。BLE 出错后可以单独重试连接，不会停止手机预览；自动重连、旧锚点续传和进程回收恢复尚未实现。首行缩进和中文标点禁则仍是后续版式工作。
