# 实施与验证计划

> 当前代码已覆盖 Texpod 的任意来源系统静音 TTS、独立手机 1bpp 预览、有界采集、手机栅格 LRU、设备镜像、可选 BLE 推页、固件 RAM LRU、网格合成和位图回退。手机和固件名称均为 Texpod；applicationId、Java 包名、BLE UUID 与固件持久化 ID 不变。真机 TTS 兼容性、手机界面、配对翻页、四种方向、断连恢复、HID 切换、内存峰值与端到端显示仍未验证，以下继续作为验收顺序。

## 先独立验证两条子链路

1. **任意阅读 App → 系统 Mock TTS → 手机本地页。** 不需要阅读器或蓝牙权限。在系统设置中选择 Texpod，到任一 App 开启朗读，正文应在手机预览出现；不需要回伴侣 App 选来源或再次开启开关。记录 App、Android 版本、请求顺序、完成/停止行为，验证静音持续推进、来源切换、队列满、错误后重读、锁屏和进程回收。手机预览和传输位图像素一致性由 JVM 测试独立覆盖。
2. **手机 → BLE → X3/X4 1bpp 位图 → 按键翻页。** 先证明 Peripheral、Android GATT、分片和刷屏在真机可用。测实际 ATT MTU、有效吞吐、单页暂存与显示缓冲峰值，以及 HID → Texpod → HID 切换和睡眠退出。必要时比较同画质的压缩位图作为测量对照，不先承诺压缩协议。

“试试示例”提供完全不依赖来源 App 的本地输入，应验证首屏、短页增长、满页、上一页/下一页、清除、字体回退和屏幕旋转；它不是实际第三方 TTS 验收的替代品。手机预览的上一页/下一页只操作手机游标；设备按键以设备确认页为锚点，二者共享分页历史但不相互覆盖当前位置。

当前代码已把 `PAGE_GRID`＋初版双端 LRU 接入真实 TTS 文本推送路径。主机测试已覆盖手机栅格 LRU、设备镜像和固件 RAM LRU 的命中、淘汰、重绑及确认时序；两端还共享固定帧向量。首版只在手机侧预排相邻页；如真机前后翻明显等待，再评估是否增加**一个**设备端待显示页预取槽，不引入页面历史缓存作为前置条件。BLE 出错可单独重试，自动重连、旧锚点续传和进程回收恢复尚未实现。

## 验收场景

- **输入与版式：** 中文、英文和数字混排、段落和标点、换行、短页、合法重复文字、生僻字与组合字符。按手机页面来源范围核对已接收正文不漏、不重、不擅改；新块到达不能悄悄重排已交付页面。以同一 1bpp 版式对照手机画面和图集合成，检查字形裁剪与混排观感。
- **网格：** 空白格、行中换行、满行自然折行、显式空行、恰好填满、短页、未知操作符、截断和越界。坏页不能提交；新字形不齐时不能画到一半再逐字请求。
- **前后推页：** 真实操作 `下一页 → 上一页 → 下一页`；页面标识允许回退，而推送序号递增。覆盖快速按键、重复请求、迟到响应、确认丢失、刷屏失败、`NO_PAGE`、BLE 超时、断线重连。重复推送只重发结果不重复刷屏；没有可推页或断连时不推进位置。用断线前后不同的确认时点验证锚点，不把未确认的翻页当作进度。
- **双端 LRU：** 分别验证手机栅格 LRU 与设备镜像命中，不能把前者误当成后者。覆盖冷启动、热复用、命中提升、非工作集淘汰、槽位重绑、位图池碎片、容量刚好、差一字节、槽位耗尽、整表重置、单页溢出走位图、半包、旧纪元和旧修订号。同一页重复字形按最后出现位置计算顺序；`PAGE_BITMAP` 不改变 LRU。只有在 `DISPLAYED` 后手机镜像才提交，重复推送不重复提升，失败或确认丢失不会留下两端各执一半的状态。后退仍走新推送，不使用设备旧页重放。
- **设备生命周期：** X3/X4 分别验证实际安全区、方向、位序、刷新模式和缺少位图暂存资源的行为。覆盖反复进入/退出、连接中超时、手动与空闲睡眠、恢复和无线角色切换失败。不会遗留任务、句柄或缓存，也不以保持 BLE 连接阻止正常休眠。

## 本次主机验证记录

- Android：102 项 JVM 测试通过，Debug APK 构建、Lint 通过。真机验收：翻到中间页，将字号从 24 px 调到 30 px，确认首字符不变、相邻页按新字号显示，随后验证两个方向的独立换源实验：旧页暂留，第一次向任一方向翻页均进入新流第一页，不能退回旧流。连接阅读器时再验证其最后确认页及字形缓存刷新。
- 固件：27 项 Texpod 主机测试、4 项 C3 BLE 配置测试、4 项固件更新测试和 51 项发布打包测试通过。回归覆盖 MTU 23 分片、网格原地校验、缓存命中字形的绘制参数，以及更新失败时不切换启动槽。
- X3/X4 的 `default` 和 `gh_release` 均通过构建。两个 `firmware.bin` 分别为 6,435,776 B 和 6,378,672 B，比 6,553,600 B 的 OTA 槽分别小 117,824 B 和 174,928 B。ESP 镜像校验和、SHA-256、设备标签和分区表检查通过。两个环境的 bootloader 和分区二进制与修改前逐字节相同；SD 更新器和恢复入口未改动。以上不是运行时堆内存数据，也不等于实机 SD 升级成功。
- S3 `sticky` 的 81,060 B / 6,243,755 B 为此前构建历史，不冒充本次结果；其余 S3 环境未逐一补验，不宣称完整 `ci-check` 全绿。
- Windows 全量主机测试在下载的 CrossPoint Simulator 的 `esp_random.h` 处以“Unsupported host OS for simulator random source”停止，因此不能宣称全量 CTest 通过；Texpod 过滤测试已独立编译并实际执行。没有为绕过这一平台限制修改模拟器源码。
- 当前无可用 Android 设备或模拟器，也未连接 X3/X4。已检查 APK 的 Texpod 标签、系统 TTS 配置和签名，但未进行手机界面实机检查、真实第三方 TTS、BLE 配对、刷屏、旋转、连续会话、睡眠与 HID 切换验收；也未刷写本次固件。以下性能和兼容性项目仍需实测。

## 性能对照与冻结项

保持正文、视觉参数、方向和刷新策略一致，连续测至少 100 页，另测首屏、后退和重连。分手机栅格冷/热、设备 LRU 冷/热、淘汰重绑、整表重置和大量新字报告：

- 网格推送（含字形、显式槽位绑定、帧头与重传）与同画质位图的每页及累计字节；相同正文分别测原始位图及可行的压缩对照。
- 手机断段、分页、栅格 LRU 冷/热耗时；BLE 协商 MTU、有效吞吐、重传和接收时长。
- 按键到开始刷屏、到刷屏完成的 P50/P95，分前翻、后翻、设备缓存命中及有无字形增量报告。不要用只有双端暖缓存的数据承诺首屏或断线后延迟。
- 启动、接收与渲染重叠、退出后内存的峰值与回收：手机栅格 LRU 和镜像占用、设备索引/位图池/候选记录峰值、空闲堆、最大连续块、任务栈余量、暂存 SD 开销和异常分配；并检查编译产物的 OTA 槽余量，测连接中、空闲及睡眠功耗。

首轮测量后确认默认字体和主题、支持的 Android/目标 App、双端条目/字节/槽位上限、修订号宽度、传输参数与延迟/功耗门槛。不得降低现有 HID 内存保护、增加第二个全屏缓冲或把模拟器结果作为真机验收。通用排版、语音输出和 iOS 不列入当前实施计划。

### SD 预制字体构建

从固定的 [Noto CJK 修订](https://github.com/notofonts/noto-cjk/tree/165c01b46ea533872e002e0785ff17e44f6d97d8) 获取 `Sans/OTF/SimplifiedChinese/NotoSansCJKsc-Regular.otf` 和根目录 `LICENSE`（保存为 `OFL.txt`），一起放入 `build/texpod-font-source/`。安装 `freetype-py==2.5.1` 并使用 FreeType 2.13.2，从仓库根目录执行 `python scripts/bake_texpod_fonts.py build/texpod-font-source build/texpod-baked`。在 `android/` 构建 APK 时传入 `-PtexpodBakedAssets=<build/texpod-baked/android-assets 的绝对路径>`，使 APK 和 SD ZIP 使用匹配的字形编号及版本。

### SD 字形流真机验收

1. 在 X3/X4 上从「SD 卡固件更新」选择 `gh_release/firmware.bin`，不要选择合并的 `firmware.factory.bin`。安装包含预制字体的 Android APK（0.4.2），将 `texpod-sd-fonts.zip` 解压到 SD 根目录，得到 `/.crosspoint/texpod-fonts/`。再在两端打开 Texpod。首次连接和切换已预制的字号时，分片记录应有 `FONT_QUERY`、没有 `FONT_CHUNK`。若预制包及兼容的已安装包均不可用，需在「阅读器性能」明确选择重新安装；测试中断上传应断开 BLE，不要在固件升级过程中断电。
2. 加载示例或一段中文与拉丁字母混排文本。在「阅读器性能」确认页面类型为「SD 字形流」。页面数据应为 `PAGE_GLYPHS`，没有 `PAGE_BITMAP`、`FONT_CHUNK` 或字形位图。停顿后，前后页的准备会产生 `PAGE_PREPARED`（没有相邻页时是 `NO_PAGE`），不应刷新墨水屏。前翻、后退和重翻，比较停顿前后的 SD 读取次数与耗时。
3. 在有多页余量的地方快速按三次下一页，预期跳三页；交替按下一页和上一页，预期按净偏移量移动。确保在刷屏提交之前完成这组按键：已开始的刷新不可中断。再验证首尾页、源切换以及旧版手机或固件仍可逐页翻动。
4. 比较「阅读器翻页输入到刷新完成」，不把手机收到请求之后的计时当成端到端。结合分片到达跨度、SD 查找时间和刷新分项定位慢页；SD 查找时间已算在逐片解码绘制里，不重复相加。首屏及字体包初始化另记，不当作普通翻页。
5. FAT 字体包首次打开时检测文件簇是否连续；连续文件在 RAM 未命中时可直接定位对应簇，碎片化文件仍走常规查找。用相同字体包和页面对比两种布局下的冷查找时间及渲染结果；检测时间计入字体包打开，不计入翻页。此优化不会重写字体包。
